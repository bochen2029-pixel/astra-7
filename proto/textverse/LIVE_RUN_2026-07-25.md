## The diagnosis (why the levers existed)

The narrator path had **no inference budget of its own and no reasoning
control**. Three defects, all config, none contract:

1. **`max_tokens` was never set for the narrator.** `NarratorBundle`
   specified temperature and top_p and let `max_tokens` fall through to
   the `SamplingParams` default of **2048** — ASTRA's SPEECH budget,
   silently borrowed by a composition path.
2. **`extra_payload` was a constructor parameter no caller ever passed.**
   Reasoning therefore ran at whatever the server chat template defaults
   to, which for Qwen 3.x is on.
3. **The composition request was pretty-printed JSON** (`indent=2`) —
   pure input-token cost on the one path whose measured failure mode was
   budget exhaustion.

So a reasoning model spent an unbounded share of a speech-sized budget
thinking about its own constraints, overran, failed CLOSED on the
unclosed `<think>` (correctly, per the 6c strip rule), and handed off to
the template. On half of all turns.

**The structural argument for `thinking="off"`:** the Narrator is a
RENDERER. Its own sysprompt's closing line is "you take structured world
state and render it as in-register prose," and §15.6 makes it
calculator-bound: it may only transcribe numerics it was handed, never
derive them. There is no decision for cognition to make, so cognition is
pure cost. This is the F-LIVE-11 / F-LIVE-16 lesson one seam deeper: not
"strip the cognition" but **do not generate it**.

**Pre-flight smoke** (identical composition request, live 9B), which is
why the run was worth spending:

| arm | latency | raw | think tag | delivered | validator |
|---|---|---|---|---|---|
| thinking=on, 2048 | 10.9 s | 2502 ch | present | 467 ch | passed |
| thinking=off, 1024 | **2.3 s** | 435 ch | **absent** | 435 ch | passed |

The three surviving fallbacks (`5.2`, `42`, `4.2`) are **all genuine

invention remains.

**F-LIVE-22 — the shakedown catch: a perception-path parity defect.
`state_coherent` collapsed 0.493 → 0.052, and 82 of 84 failures are ONE
class.** The `<state>` section emitted `kinematic_regime is 0` instead
of naming the regime `REST`.

The reading matters more than the number. With thinking ON, the model
had budget to *guess* the enum → label mapping and got it right about
half the time (that is all 0.493 ever was). With thinking OFF it
faithfully transcribed what it was handed — which for a calculator-bound
renderer is the **more correct** behavior: it stopped inventing a label
nobody gave it. The gate was right to fail it. **The request was wrong.**

The template path has always rendered `regime_label(state_bus.regime)`
itself (`perception_assembler.py:88`, `:158`). The narrator path was the
only consumer in the system asked to translate an enum it was never
given a table for. That is exactly the rule F-LIVE-14 settled for τ —
derived presentation values are computed by the assembler, never
inferred downstream — simply never applied to regime.

**Closed at the request seam:** the composition request now supplies the
regime label and the body-name list under an explicit "already computed;
do not re-derive" instruction. Four tests pin it, including the
bodyless-StateBus edge and the do-not-re-derive instruction itself
(the instruction is what makes it a contract rather than a hint).

**Honest note on method:** run #10 alone would have supported a 16×
headline win on the R-4 number while perception bundles were failing
coherence on 91 of 93 turns. The 6b/6c shakedown-then-clean-run
precedent is what caught it. It earned its keep for the third time.
