# LIVE_RUN_2026-07-25 (6f) — the replication study: the bench gets error bars

**Continues** `LIVE_RUN_2026-07-19.md` (runs #1–#9) and
`LIVE_RUN_2026-07-25.md` (runs #10–#11, work item 6e). This file carries
runs **#12–#17** and findings **F-LIVE-25…27**.

**Why this exists.** Every finding in the series so far was reported from
ONE run per arm and hedged as "directional," because a live narrator
suite cost ~2 hours and replication was unaffordable. 6e took the
narrator suite to ~16 min and the template suite to ~4. Replication
became cheap, so single-run claims lost their excuse. **The first thing
spent on that budget is the question 6e explicitly left open.**

**Design:** 3 template + 3 narrator replicates, **interleaved**
(t,n,t,n,t,n) so any drift across the hour hits both arms equally. Same
34-scenario library, same model (Qwen 3.5 9B Q5_K_M), same sampling,
same code (`astra/` at `2d6cb72` for every run). Nondeterministic
sampling (T=0.7, no seed) is the variance under measurement, not a
defect. Analysis by `scripts/compare_runs.py`; artifacts under
`scenarios/output/live_run_6f_{template,narrator}_{1,2,3}/`.

**Method note, stated up front:** with n=3–4 per arm this study does no
significance testing, because n=3–4 does not support it. The reported
predicate is whether the arms' observed RANGES separate — the weakest
honest claim of a real difference. Overlap is reported as **NOT
ESTABLISHED**, which constrains what may be claimed; it is not a proof
of equality.

## The headline: 6e's open question resolves, and resolves AGAINST the
## reading the single run suggested

6e closed with this flag: *"tool_valid 0.810 is the new floor gate and
drifts down across the series. Whether narrator perception makes it
worse than the template path is NOT established. Flagged, not
concluded."*

Measured, the direction is **opposite**:

| **state_coherent** | **1.000** [1.000, 1.000] | 0.919 [0.871, 0.948] | **ESTABLISHED**, template higher |

| persona_stable | 1.000 [1.000, 1.000] | 0.980 [0.956, 1.000] | not established (touching) |
| no_leak | 0.926 [0.909, 0.941] | 0.922 [0.908, 0.926] | not established |
| grammar_parse | 0.994 [0.988, 1.000] | 1.000 [1.000, 1.000] | not established |
| memory_coherent | 1.000 | 1.000 | not established |

**F-LIVE-25 — the run-#11 tool_valid reading was noise, and pointed the
wrong way.** Run #11's 0.810 against run #9's template 0.884 suggested
narrator perception was degrading tool use. Across four narrator runs
the mean is 0.885 versus template's 0.826, and 0.810 turns out to be the
low tail of a wide narrator band, not a level. Nothing about the
narrator path is established as harming tool validity; if anything the
point estimate leans the other way. **The 6e ledger's hedge was correct
and its implied direction was not — this is exactly the error single-run
reporting produces, caught the first time error bars existed.**

**The fragility is the lesson, and it is worth more than the result.**
At n=3 the tool_valid ranges DID separate (template [0.798, 0.843] vs
narrator [0.856, 0.938]) and the study would have concluded "narrator
significantly higher." Adding the legitimate fourth narrator replicate
(run #11 — same `astra/` code, same config, predating only the
`git_head` provenance field) widens the band to [0.810, 0.938] and the
separation dissolves. **A conclusion that flips on one replicate was
never a conclusion.** Reported at n=4; the n=3 version is recorded here
only as the cautionary artifact.

That near-miss is now defended in code: `compare_runs.py` treats the
code revision as part of arm identity, and emits a **provenance warning**
whenever unrevisioned runs sit beside revisioned ones, because excluding
a real replicate narrows bands and manufactures separations. Both
behaviors are pinned by tests.

## What IS established

**F-LIVE-26 — the narrator path costs ~0.08 of state coherence, and the
finding is robust.** Template scores **1.000 on state_coherent in all
three runs, zero variance**; the narrator arm sits at 0.919 [0.871,
0.948] and the separation survives the n=4 sensitivity. This is
F-LIVE-20's residue finally quantified with error bars rather than
asserted from one run, and it is the empirical warrant the narrator
sysprompt work was missing: the gap is real, it is ~0.08, and it is
larger than the narrator arm's own run-to-run spread (0.077). A
sysprompt change can now be evaluated against a known floor instead of
against noise.

**F-LIVE-19's closure holds across four independent runs.** Fallback
rates 0.011 / 0.022 / 0.032 / 0.022 — mean 0.022, range [0.011, 0.032],
never once approaching run #8's 0.506. The truncation class does not
reappear. This is no longer a single-run claim.

**Model-Off Replay: 3/3 on every one of the six runs — 18/18 this study,
51/51 lifetime across seventeen live runs.** The §5.3/§2.4 predicate has
never once failed.

**Narrator perception roughly triples tool_valid variance.** Spread
0.128 (narrator, n=4) vs 0.045 (template, n=3). The means may not
separate, but the narrator path is visibly less stable turn to turn.
Recorded as a lead, not a conclusion: n is small and spread is a noisy
statistic at n=3–4.

**Economics, replicated:** template 4.5–6.0 min, narrator 11.8–33.8 min
per 34-scenario suite. The narrator arm's own spread is large enough
that the 6e "15.8 min" figure should be read as a sample, not a
constant.

## F-LIVE-27 — the crash the replication surfaced: ctx exhaustion at 8192

`live_run_6f_template_2` lost `heartbeat_warp_cruise` to
`HTTP 400: request (14454 tokens) exceeds the available context size
(8192 tokens)`. **Template path, 6-turn heartbeat scenario, 1 of 3
runs.** Nothing to do with 6e or 6f: the template path is untouched by
both. It is stochastic because ASTRA's own output lengths vary, so
accumulated history tips over the limit on some runs and not others.

Two consequences worth naming:

1. The bench's default `--ctx-size 8192` is now a measured constraint,
   not a comfortable margin. The longest scenarios sit close enough to
   the ceiling that ~1/3 of runs can lose one. As the library grows and
   scenarios lengthen, this gets worse, silently — a crashed scenario is
   excluded from gate means, so the run still LOOKS clean.
2. Historical single-run results may already have been affected without
   anyone noticing. Runs #9/#10/#11 recorded 0 crashes, so this is rare,
   but "rare" was invisible until something ran the same config three
   times.

Routed as a config item (raise ctx for the long scenarios, or bound
history growth) rather than a contract matter. Not fixed here: it is
outside 6f's scope and deserves its own measured change.

# AUDIT ADDENDUM (6j, 2026-07-26): the non_degenerate row downgrades

The headline table above marks `non_degenerate` (template 0.995 [0.994,
0.995] vs narrator 0.987 [0.979, 0.992]) as **ESTABLISHED**. The 6j
session audit re-examined it under the count discipline 6i introduced:

- Raw events: **template 3 failing turns, narrator 10** (of ~273/372).
- The separation SURVIVES every valid replicate available (template n=4
  adding run #9, whose non_degenerate leg is untouched by the 6e narrator
  changes; narrator n=4 as published) — so unlike F-LIVE-30 it is not
  withdrawn.
- But 3-versus-10 events is squarely the fragile-count class whose
  sibling claim flipped at n=6. **Downgraded: ESTABLISHED → PROVISIONAL
  (fragile, few events).** It should not be cited as a settled
  path-effect without a properly powered re-measurement.

The same audit strengthened two claims above rather than weakening them:
the 6h treatment `state_coherent` 1.000 was re-verified against the
documented substring limitation (87 turns naming hot_earth; **zero**
turns where `earth` was credited only via the substring inside "hot
earth"), and the replay legs of runs #18–#26 — which the runner's exit
code could not attest (the loop ends in `echo`) — were verified from
artifacts: **9/9 runs, 27/27 replays byte-identical**, lifetime now
**78/78 across 26 live runs**.

Instrument follow-through: the fragility criterion itself was corrected
(min-arm > 0 exempted every zero arm, letting a hypothetical 0-vs-2-event
"separation" pass unflagged; now max-arm ≤ 20, which still leaves
24-vs-0-class closures alone), and the comparator now warns when any arm
has n=1, since a band of one run is a point.
