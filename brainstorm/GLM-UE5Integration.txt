## Phase 1: The CUDA-DX12 Zero-Copy Spine

The biggest mistake CUDA plugins make is copying data from GPU → CPU → GPU via `RHICreateTexture2D`. This kills framerate. We will use **DirectX 12 Shared Resources** and **Cross-Adapter Fences**.

### The Interop Architecture

```cpp
// ================================================================
// WarpInterop.h (UE5 Plugin Core)
// Manages the GPU memory sharing between UE5 (DX12) and CUDA
// ================================================================
#pragma once

#include "CoreMinimal.h"
#include "RHI.h"
#include "D3D12RHI.h"

class WARPFIELD_API FWarpInterop
{
public:
    void Init();
    void Destroy();

    // Call this at the start of the UE5 Frame
    void BeginFrame();
    // Call this at the end of the CUDA dispatch
    void EndFrame();

    FRHITexture2D* GetWarpFieldTexture() const { return WarpFieldTextureRHI; }
    FRHITexture2D* GetLensingBufferTexture() const { return LensingBufferRHI; }

private:
    // UE5 RHI Resources (Created via FRHIDevice)
    FTextureRHIRef WarpFieldTextureRHI;
    FTextureRHIRef LensingBufferRHI;

    // CUDA Handles for the SAME memory
    cudaGraphicsResource* CudaWarpResource = nullptr;
    cudaGraphicsResource* CudaLensingResource = nullptr;
    cudaExternalSemaphore_t D3DFenceSemaphore = nullptr;
    cudaStream_t CudaStream = nullptr;

    // DX12 Synchronization
    ID3D12Fence* D3DFence = nullptr;
    uint64 CurrentFenceValue = 0;
};
```

### The Synchronization Dance

UE5 and CUDA run on separate GPU queues. If UE5 reads the texture while CUDA is writing, the frame tears. We use **DX12 / CUDA Shared Fences**.

```cpp
// ================================================================
// WarpInterop.cpp
// ================================================================
void FWarpInterop::Init()
{
    // 1. Create DX12 Textures with SHARING flag
    FRHITextureCreateDesc Desc = FRHITextureCreateDesc::Create2D(
        TEXT("WarpFieldTarget"),
        FIntPoint(1920/2, 1080/2), // Half-res for volumetrics
        EPixelFormat::PF_FloatRGBA,
        ETextureCreateFlags::ShaderResource | ETextureCreateFlags::UAV |
        ETextureCreateFlags::Shared // CRITICAL: Allows CUDA to see it
    );
    WarpFieldTextureRHI = RHICreateTexture(Desc);

    // 2. Get the underlying ID3D12Resource
    ID3D12Resource* D3DResource = static_cast<ID3D12Texture2D*>(WarpFieldTextureRHI->GetNativeResource());

    // 3. Register with CUDA
    cudaGraphicsD3D12RegisterResource(&CudaWarpResource, D3DResource, cudaGraphicsRegisterFlagsNone);

    // 4. Create Shared Semaphore (DX12 Fence -> CUDA Semaphore)
    // This is the 2026 standard for cross-API sync
    ID3D12Device* D3DDevice = static_cast<ID3D12Device*>(GDynamicRHI->RHIGetNativeDevice());
    D3DDevice->CreateFence(0, D3D12_FENCE_FLAG_SHARED, IID_PPV_ARGS(&D3DFence));
    
    HANDLE SharedHandle;
    D3DDevice->CreateSharedHandle(D3DFence, nullptr, GENERIC_ALL, nullptr, &SharedHandle);

    cudaExternalSemaphoreHandleDesc SemDesc = {};
    SemDesc.type = cudaExternalSemaphoreHandleTypeD3D12Fence;
    SemDesc.handle.fence = SharedHandle;
    cudaImportExternalSemaphore(&D3DFenceSemaphore, &SemDesc);

    cudaStreamCreate(&CudaStream);
}

void FWarpInterop::BeginFrame()
{
    // UE5 has finished rendering the previous frame.
    // Signal CUDA that it can write to the textures.
    CurrentFenceValue++;
    D3DFence->Signal(CurrentFenceValue);

    // Wait on CUDA side
    cudaExternalSemaphoreWaitParams WaitParams = {};
    WaitParams.params.fence.value = CurrentFenceValue;
    cudaWaitExternalSemaphoresAsync(&D3DFenceSemaphore, &WaitParams, 1, CudaStream);

    // Map the texture for CUDA writing
    cudaGraphicsMapResources(1, &CudaWarpResource, CudaStream);
    // ... dispatch kernels ...
}

void FWarpInterop::EndFrame()
{
    // Unmap so UE5 can read it
    cudaGraphicsUnmapResources(1, &CudaWarpResource, CudaStream);

    // Signal UE5 that CUDA is done
    CurrentFenceValue++;
    cudaExternalSemaphoreSignalParams SignalParams = {};
    SignalParams.params.fence.value = CurrentFenceValue;
    cudaSignalExternalSemaphoresAsync(&D3DFenceSemaphore, &SignalParams, 1, CudaStream);

    // UE5's RHI thread will wait on D3DFence before reading the texture in the Post-Process pass
}
```

## Phase 2: Starfield Injection via `ISceneViewExtension`

Bypassing UE5's `FSkySphere` is mandatory. The default sky is a 2D cubemap meant for static cameras. We need our CUDA ray-marched starfield to be the **background of the G-Buffer** before Lumen calculates Global Illumination.

### The View Extension

```cpp
// ================================================================
// WarpStarfieldViewExtension.h
// Injects the starfield before the Base Pass
// ================================================================
#pragma once

#include "CoreMinimal.h"
#include "SceneViewExtension.h"

class FWarpStarfieldViewExtension : public FSceneViewExtensionBase
{
public:
    FWarpStarfieldViewExtension(const FAutoRegister& AutoRegister);

    // This fires before UE5 renders the Base Pass (Nanite)
    virtual void SetupViewFamily(FSceneViewFamily& InViewFamily) override {}
    virtual void SetupView(FSceneViewFamily& InViewFamily, FSceneView& InView) override {}
    
    // THE HOOK: Render before Base Pass
    virtual void PreRenderViewFamily_RenderThread(FRDGBuilder& GraphBuilder, FSceneViewFamily& InViewFamily) override;

private:
    void RenderStarfield(FRDGBuilder& GraphBuilder, FSceneViewFamily& ViewFamily);
};
```

### The RDG Pass Implementation

```cpp
// ================================================================
// WarpStarfieldViewExtension.cpp
// ================================================================
void FWarpStarfieldViewExtension::PreRenderViewFamily_RenderThread(
    FRDGBuilder& GraphBuilder, FSceneViewFamily& InViewFamily)
{
    // 1. Get the Scene Color (which is currently empty/cleared)
    FRDGTextureRef SceneColor = GraphBuilder.TryFindExternalTexture(InViewFamily.RenderTarget->GetRenderTargetTexture());
    if (!SceneColor) return;

    // 2. Add a custom RDG pass
    GraphBuilder.AddPass(
        RDG_EVENT_NAME("WarpStarfield"),
        PassParameters,
        ERDGPassFlags::Compute,
        [this, SceneColor](FRHICommandList& RHICmdList)
    {
        // 3. Dispatch CUDA Kernel
        // (Assuming Interop BeginFrame already mapped the resource)
        float4* d_scene_color_ptr;
        cudaGraphicsResourceGetMappedPointer((void**)&d_scene_color_ptr, nullptr, Interop->GetSceneColorResource());

        dim3 threads(16, 16);
        dim3 blocks((Width + 15) / 16, (Height + 15) / 16);
        
        render_starfield<<<blocks, threads, 0, CudaStream>>>(
            d_scene_color_ptr,
            StarsBuffer,
            CubemapTexture,
            StarfieldConstants
        );
    });
}
```

**Why this is brilliant:** When Lumen calculates indirect lighting, it traces rays against the G-Buffer. By injecting the starfield *before* the base pass, the bright blue O-class stars and the redshifted wake will **cast Lumen Global Illumination** onto the back of your ship's hull. The warp field will bounce realistic light onto the geometry.

## Phase 3: Warp Field & Lensing via Post-Process Material

The volumetric warp field is rendered at half-resolution to a shared texture. We use a **Post-Process Material** to composite it and apply the gravitational lensing to the final HDR image.

### The Material Blueprint

Create a `M_WarpComposite` Post Process material.
*   **Blendable Location:** `Before Tonemapper` (we need HDR data for lensing).
*   **Output Node:** Emissive Color.

**The Material Graph Logic:**

1.  **Sample Scene Color (Lensed):**
    *   Get screen UV.
    *   Sample the `LensingBuffer` (R32G32F). This contains the 2D screen-space offset vector.
    *   Offset the UV: `NewUV = UV + LensingOffset * LensingStrength`.
    *   Sample `SceneColor` at `NewUV`. This creates the gravitational lensing distortion of the Nanite geometry and Lumen lighting behind the warp field.

2.  **Sample Warp Field Volume:**
    *   Sample the `WarpFieldTexture` (Half-res, RGBA). R/G/B = Emission Color, A = Opacity/Density.

3.  **Chromatic Aberration (The Einstein Ring effect):**
    *   Instead of one UV offset, calculate three offsets based on wavelength (R, G, B).
    *   `OffsetR = UV + LensingOffset * 1.02`
    *   `OffsetG = UV + LensingOffset * 1.00`
    *   `OffsetB = UV + LensingOffset * 0.98`
    *   This creates a spectral splitting effect around the warp bubble's gravitational shear zones.

4.  **Composite:**
    *   `FinalColor = LensedSceneColor * (1 - WarpAlpha) + WarpEmission`
    *   Connect to Emissive.

## Phase 4: CFD Asset Pipeline (`UDataAsset`)

You need a way for the Art Director to drag-and-drop the CFD data onto the ship Blueprint in the UE5 Editor.

### The C++ Asset Type

```cpp
// ================================================================
// WarpCFDAsset.h
// Custom UAsset wrapping the RBF network and Hull SDF
// ================================================================
#pragma once

#include "CoreMinimal.h"
#include "Engine/DataAsset.h"
#include "WarpCFDAsset.generated.h"

USTRUCT(BlueprintType)
struct FWarpRBFNode
{
    GENERATED_BODY()
    UPROPERTY(EditAnywhere, Category="Warp|CFD")
    FVector Position; // Local space
    
    UPROPERTY(EditAnywhere, Category="Warp|CFD")
    float Radius;
    
    UPROPERTY(EditAnywhere, Category="Warp|CFD")
    FVector Velocity;
    
    UPROPERTY(EditAnywhere, Category="Warp|CFD")
    float Pressure;
    
    UPROPERTY(EditAnywhere, Category="Warp|CFD")
    FVector Vorticity;
};

UCLASS(BlueprintType)
class WARPFIELD_API UWarpCFDAsset : public UDataAsset
{
    GENERATED_BODY()

public:
    UPROPERTY(EditAnywhere, Category="Warp|CFD")
    TArray<FWarpRBFNode> RBFNetwork;

    UPROPERTY(EditAnywhere, Category="Warp|CFD")
    FIntVector SDFDimensions = FIntVector(256, 256, 512);

    UPROPERTY(EditAnywhere, Category="Warp|CFD")
    FString SDFRawFilePath; // Path to the .raw file generated by Python

    // Transient GPU handles
    cudaSurfaceObject_t HullSDFSurface;
    bool bIsUploadedToGPU = false;

    void UploadToGPU()
    {
        if (bIsUploadedToGPU) return;
        
        // 1. Allocate CUDA 3D Array for SDF
        cudaChannelFormatDesc channelDesc = cudaCreateChannelDesc<float>();
        cudaExtent extent = make_cudaExtent(SDFDimensions.X, SDFDimensions.Y, SDFDimensions.Z);
        cudaMalloc3DArray(&SDFArray, &channelDesc, extent);

        // 2. Load raw file from disk and copy to GPU
        TArray<float> SDFData;
        // ... File IO logic ...
        cudaMemcpy3DParms copyParams = {};
        copyParams.srcPtr = make_cudaPitchedPtr(SDFData.GetData(), SDFDimensions.X * sizeof(float), SDFDimensions.X, SDFDimensions.Y);
        copyParams.dstArray = SDFArray;
        copyParams.extent = extent;
        copyParams.kind = cudaMemcpyHostToDevice;
        cudaMemcpy3D(&copyParams);

        // 3. Create Surface Object
        cudaResourceDesc resDesc;
        resDesc.resType = cudaResourceTypeArray;
        resDesc.res.array.array = SDFArray;
        cudaCreateSurfaceObject(&HullSDFSurface, &resDesc);

        // 4. Copy RBFNetwork to __constant__ memory
        cudaMemcpyToSymbol(c_rbf_nodes, RBFNetwork.GetData(), RBFNetwork.Num() * sizeof(FWarpRBFNode));

        bIsUploadedToGPU = true;
    }
};
```

## Phase 5: MetaSound Integration (The Audio Engine)

In UE 5.5, `MetaSounds` is the standard. We will push the `AudioExtractionPayload` (640 bytes) directly into a custom MetaSound Generator, bypassing the CPU main thread entirely.

### The MetaSound Vertex

Create a custom MetaSound node called `Warp Field Listener`.

```cpp
// ================================================================
// WarpMetaSoundNode.cpp
// ================================================================
// Define the output pins of the node:
// - Float: Metric Strain
// - Float: Tidal Force
// - Float: Vorticity
// - Float: Interference

class FWarpMetaSoundGenerator : public TMetaSoundGenerator<FWarpMetaSoundGenerator>
{
    virtual void Execute(FAudioBuffer& Output) override
    {
        const AudioExtractionPayload* Payload = WarpAudioBridge->GetPayload();

        // Bridge Sensor Data to Audio Rate
        // E.g., Map Payload->sensors[0].metric_rate to a control voltage
        float strain_cv = FMath::Clamp(Payload->sensors[0].metric_rate * 10.0f, -1.0f, 1.0f);

        // Push to MetaSound graph
        SetOutputValue(TEXT("StrainRate"), strain_cv);
        
        // The MetaSound graph then uses these CVs to drive:
        // - Sine Oscillators (Sub-bass drone)
        // - FM Synthesis nodes (Shear tearing)
        // - Granular nodes (Turbulence)
    }
};
```

This means your Audio Designer opens the MetaSound Editor, sees the `Warp Field Listener` node, and can wire the `Tidal Force` output directly into the Modulation Index of an FM Synth node. **No C++ audio coding required for sound design.**

    *   CUDA updates the Chaos simulation and Tensor Core AI.

    *   UE5's Post-Process material applies UV lensing distortion (with Chromatic Aberration) and additive composites the warp field.

    *   MetaSounds read the payload and generate sub-bass and FM tearing in real-time.
