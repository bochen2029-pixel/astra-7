### D2 — stdio_server op surface vs Narrator-LLM tool surface (BLOCKER)

- **stdio_server exposes** (proto/astra_nexus.cpp:931-957): `health`, `version`, `compute_apparent_rate` — **3 ops**.
- **Spec §6.4 Narrator-LLM tools:** `physics_query`, `astrometric_query`, `ship_state_query`, `composition_rule_evaluate`, `retarded_time_solve`, `kepler_at` — **6 ops**.
- **Severity:** BLOCKER for the Narrator-LLM track (§6.4) and for §15.6 calculator-bound LLM agency on the Narrator side. ASTRA's track is fine (her TOOL API is `astra/ship/api.py`).
- **Reconciliation:** **code conforms to spec.** Add the 6 ops to `astra_nexus::stdio_server::dispatch()` as a series of additive case-statements (the existing pattern is well-shaped for it). Each op routes to existing or new C++ functions; the dispatch surface is the only thing that grows.

### D3 — StateBus missing `WarpState` + `cryosleep_active` (MAJOR)

- **Spec §4.2 + §4.6 + §3.3:** WarpState `{phase: charging|cruising|dropping, W: float, charge_progress: float}` + `cryosleep_active: bool`.
- **Code:** [state_bus/schema.py:112](proto/textverse/astra/state_bus/schema.py:112) `StateBus` has no warp fields; cryosleep is implicit only via `Regime.CRYOSLEEP` bit.
- **Severity:** MAJOR. The §3.3 `detect_regime(state)` predicate references `state.warp_W` and `state.warp_phase` literally; the §4.6 SaveFile schema requires `WarpState`. Warp-engage scenarios (`regime_warp_engage.yaml`) can run today only because no code actually reads `state.warp_W`.
- **Reconciliation:** **code conforms to spec.** Add `WarpState` model to `state_bus/schema.py`; add `warp: WarpState | None = None` and `cryosleep_active: bool = False` (or keep cryosleep purely as `Regime.CRYOSLEEP` and lock that as the convention). Single commit; one new test for the model + one for `detect_regime()` interaction.

### D4 — `ReelEntry` minimum fields vs spec §4.6 (MAJOR)

- **Spec §4.6:** 8 canonical fields including `t_cosmic_at_write` (v0.126 marked **required** for §3.9 dual-clock journal), `t_emit_event`, `regime_at_write`, `author_instance_id`, `retrieval_metadata`.
- **Code:** [reel.py:29](proto/textverse/astra/harness/reel.py:29) `ReelEntry` has 3 fields (`tau_ship`, `body`, `irreversibility_flag`).
- **Severity:** MAJOR. `t_cosmic_at_write` is not optional per v0.126 prose: "*required for dual-clock retrieval per §3.9*". The cryosleep journal generator (§3.9) cannot satisfy its input-contract invariant without it.
- **Reconciliation:** **code conforms to spec** for `t_cosmic_at_write` minimally. The rest (`t_emit_event`, `regime_at_write`, `author_instance_id`, `retrieval_metadata`) are reasonable to keep deferred per §4.6's "v0.125 inline placeholder" framing but should be acknowledged in `reel.py` as a v0 minimum.

### D5 — `observation_calc.py` is a re-export shim, not the §6.3 module (MAJOR)

- **Spec §6.3:** stateless module sitting between State Bus and Renderer, implementing the 12-step per-body workflow.
- **Code:** [observation_calc.py](proto/textverse/astra/physics/observation_calc.py) is **33 lines** that re-export `compute_apparent_rate` from `nexus_bridge`.
- **Severity:** MAJOR. The Narrator-LLM and the perception assembler both need full `observe()` output; the current wrapper exposes only the apparent-rate scalar. Combined with D2 (stdio_server doesn't expose `observe`), the Python side cannot reach §6.3 functionality at all.
- **Reconciliation:** code conforms to spec. Depends on D2's resolution (expose `observe` op). Once exposed, implement `observe(ship_pos, ship_velocity, t_cosmic, body_pos, body_metric_shift, regime) → ObservableState` in `observation_calc.py` as a typed bridge call.

- **Severity:** COSMETIC.

### D7 — `integrate_rapidity_step` is Euler, not RK45 (MINOR)

- **Spec §3.7, §7.3:** "**Locked:** adaptive RK4 (RK45) on 3-vector rapidity `ζ⃗`."
- **Code:** [astra_nexus.cpp:161](proto/astra_nexus.cpp:161) is a single forward-Euler step with clamp.
- **Severity:** MINOR. At game-scale `dτ_ship` step sizes (sub-second to seconds) and bounded `a_proper`, forward-Euler with the OMEGA_MAX clamp is well within 4-sig-fig γ accuracy for `γ ≤ 10⁷`. The 48-assertion suite passes including the 1g-for-1-year exact-ω test ([astra_nexus.cpp:472-478](proto/astra_nexus.cpp:472)).
- **Reconciliation:** open question. Either upgrade the C++ integrator to adaptive RK45, OR relax the spec to "first-order integrator suffices when game-scale step bound is satisfied; RK45 is the upper-bound reservation." The empirical evidence (passing test suite) favors the latter.

### D8 — StateBus minor structural divergence on `Regime` location (COSMETIC)

- **Spec §4.2:** lists `PropulsionMode flag` at State Bus root.
- **Spec §4.4:** lists `regime` inside the Time Contract `state` block.
- **Code:** [state_bus/schema.py:112](proto/textverse/astra/state_bus/schema.py:112) places `regime` inside `TimeState`, matching §4.4. State-bus root holds `time: TimeState`.
- **Severity:** COSMETIC; the spec is internally ambiguous between §4.2 and §4.4 on this. Python's choice is consistent with §4.4 prose.
- **Reconciliation:** spec revision candidate (see Pass 6).

## Executive Summary

**ASTRA-7 is in good architectural shape at the envelope, healthy in the
LLM track, and on-schedule-deferred in the Engine track.** The 48-assertion
C++ physics binary + 477-pytest textverse bench + 9-gate LCP form a
coherent measurement instrument, and Phase 1 + Sculptor v1 have closed the
loop on the canonical scenario.

**What the audit found:**

- **8 drift items.** One BLOCKER (D2 stdio_server ops too few for §6.4
  Narrator-LLM), four MAJOR (D1 Observable/ObservableState struct mismatch
  + missing edge-case flags; D3 StateBus missing WarpState + cryosleep_active;
  D4 ReelEntry missing canonical fields per §4.6; D5 observation_calc.py is
  a thin shim, not the §6.3 module), one MINOR (D7 forward-Euler vs spec
  RK45 — empirically passing), one COSMETIC (D6 stale spec version in
  astra_nexus.cpp header), one structural ambiguity (D8 Regime location
  between §4.2 and §4.4). **All drift resolves in favor of "code conforms
  to spec"** except D8 (spec revision) and D7 (debatable spec revision R5).
- **~25 implementation gaps**, of which ~15 are LLM-track / textverse-side
  (G1-G15), and ~13 are Engine-track (GE1-GE13). Engine gaps are deferred
  per §12 and §15.8, not bugs. LLM-track gaps cluster around the Narrator-LLM
  surface (§6.4) and the ephemeral instances (§4.9).
- **Test coverage is strong on what's implemented.** 48 C++ assertions cover
  §1.1, §3.2, §3.7, §3.11, §3.12, §6.3 fully. 477 pytest cover §4.1, §4.3,
  §4.6 partial, §4.9 partial, §10 (all 9 gates), §15.6, §15.7 Surface 3+4.
  Coverage gaps map cleanly to implementation gaps; no orphaned test debt.
- **5 spec revision candidates**, none structural. Mostly clarifications
  (R1, R2, R3, R4) plus one empirically-justified relaxation (R5 Euler
  sufficient at game-scale).

**Recommended sequence:** Tier 1 drift fixes (3 single-commits) → Tier 2
Narrator-LLM unblock (5 commits, opens §6.4 + §15.6 enforcement for the
second LLM) → Tier 3 research-log appends → Tier 4 ephemeral instances +
SaveFile → Tier 5 sibling docs → (Engine track is separate cadence).

The Phase 1 loop closure is real. The next bench-side gate is **Narrator-LLM
calculator-bound enforcement** — the same architectural primitive ASTRA's
TOOL channel already satisfies, applied to the second LLM in the system.
D2 + G1 + G2 are the bottleneck for this.

**Net assessment: the spec envelope holds; the textverse implementation
under-realizes it by ~30% on the LLM side (Narrator + ephemeral instances
mostly) and ~80% on the Engine side (entirely as planned). Code conforms
to spec on all of the drift items. The bench is a measurement instrument
worth trusting.**
